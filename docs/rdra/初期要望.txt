# システム名
rdra-webapp


# 最重要要求
輸入した商品をタイムリーに紹介し直接販売する。
顧客と直接つながることで商品に対する顧客の声をダイレクトに把握し商品開発につなげる。


# 背景
ABC商事は輸入販売の商社で、従来は直営店を数十店持ち、そこで小売りを行っている。
新たに Web を使った通信販売を始める。通信販売はこの会社にとってはじめて。
システム部門が中心となり、関係部署へのヒアリングで要望をまとめる。
関係する部署: 顧客、経営者、営業、オーダー部門、物流、システム部門
経営者は売上の状況を見る。システム部門はこのシステムの利用者ではない(保守のみ)。
関係する既存システム: 入荷システム、出荷システム、決済システム
経営層は、営業にはオーダー作業よりも戦略的な商品管理の仕事にシフトしてもらいたい。オーダー処理は新たにオーダー部門を用意して集約する。
営業は、多様な顧客のニーズに沿えるように入金手段を多くしてほしい。
物流は、既存の入庫、出庫システムとの連動を望んでいる。入庫、出庫システムは入荷システム、出荷システムと同じもの。
システム部門は、保守性を考え使用する技術を統一したい。
決済システム: 入金情報を通知する(決済会社の決めたフォーマットで Web サービスを呼び出す)。
出荷システム: 出荷指示を受け付け、出荷作業の完了を通知する。
入荷システム: 入荷商品の情報を通知する。
配送会社が配送終了をメールで通知する。
在庫切れのときは取引先に対して発注する。
取引先への発注(在庫切れ時の追加発注、新規商品の発注)はこのシステムで記録し、発注先への送付は従来どおりの手段で行う。
物流の出荷は朝、昼、夕方の各3時間単位の締め毎に行う。商品の入荷は午後にまとめて送られてくる。


# 業務の概要
・Webでの商品購入(顧客)
  - 購入する商品を選びカートに追加する
  - 商品を選び終えた後で購入指示を行い、決済情報と送付先の情報を入力する
  - ABC商事からのメールを確認し、記載された金額を Web で選択した決済方法に従って支払う
  - オーダー商品の現在の状態を確認する
  - 会員登録する(会員登録しなくても購入できる)
  - 出荷前のオーダーを Web でキャンセルする
・商品管理(営業)
  - 仕入れた商品を Web 上での取り扱い商品として登録、もしくは削除する
  - 商品の特性と売れた時期、売れた場所を管理する。売れた場所はマップ上に表示する売れた場所は送付先の地域とする
  - 週単位でその週の売り上げ情報を分析(場所と商品の特性)し、次週以降の商品の品揃えを検討する
  - 在庫商品について、今後追加発注しないものをマークする
  - 売れ筋商品で在庫切れによる機会損失を無くすために在庫量を多くする
  - 新規商品を販売する場合に発注する
・オーダー処理(オーダー部門)
  - オーダー確認を行い、オーダーを受理したことと支払い方法を顧客にメールで通知する
  - 決済システムの入金情報通知を受けてシステムがオーダーと照合し、照合できないもの・金額が異なるものだけオーダー部門が入金確認を行う
  - 出荷指示の前に、システムがオーダー別の在庫を確認し、在庫切れのオーダーを入荷待ちにする
  - 在庫切れのとき、取引先に追加発注する
  - 入金が確認されたオーダーの出荷指示を行い、出荷指示はそのまま出荷システムへ連携される
  - 入金額が異なる場合は、顧客とメールもしくは電話で差額を確認し、差額の追加支払いを依頼する
  - 入金額が多すぎた場合は、顧客に連絡し差額を返金する
  - 返品をメールもしくは電話で受け付ける
  - 配送会社による配送終了のメール通知を確認し、対応するオーダーを完了する
・出荷と入荷(物流)
  - 締め毎に商品を出荷する(物流は出荷作業のみを行う)
  - 入荷情報を入荷システムに入力する。その情報は入荷システムから当システムに送られ、当システムは入荷待ちになっているオーダーの入荷待ちを解除する
・顧客の声の把握
  - 購入した顧客が商品のレビュー・感想を Web で投稿する
  - 営業が商品ごとにレビュー・感想を集計し、商品開発の検討に使う


# スコープ外
直営店での販売・店舗の在庫。直営店と Web の在庫は共有しない。
配送会社とのシステム連携(配送終了はオーダー部門がメールを見て完了にする)。


# その他
売れた時期は週単位で集計し、月単位でも見られるようにする。
